# Qogam

Flutter-приложение для Android и iOS. По умолчанию работает с backend API 0.3.1 (http://10.8.0.53:8000). Снимок Swagger: [docs/openapi.json](docs/openapi.json); состояние интеграции: [docs/BACKEND_CONTRACT.md](docs/BACKEND_CONTRACT.md).

## Запуск и установка

Окружение: Flutter 3.41.8, Dart 3.11.5, Android SDK 36.

```powershell
flutter pub get
flutter devices
flutter run -d <device-id> --dart-define=QOGAM_API_URL=http://10.8.0.53:8000
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

APK: build/app/outputs/flutter-apk/app-debug.apk. Телефон должен иметь доступ к сети backend. Для локального демо: flutter run --dart-define=QOGAM_DEMO=true. Демо использует отдельный источник с отметкой «Демо» и не отправляет обращения на сервер.

Для iOS нужен Mac с Xcode. На Windows iOS-сборка не проверена. Debug APK предназначен для разработки.

## Реализовано

- Тема, общие компоненты, ru/kk и навигация: Рядом / Мои заявки / Мой дом / Профиль.
- Серверные города, категории, статусы, опубликованные проблемы: поиск, фильтры, пагинация, карта OpenStreetMap с серверными маркерами и кластерами. Карта и список используют общий фильтр и видимую область.
- Публичная карточка и собственное обращение, история с пагинацией, фотографии из серверного ответа, актуальные статусы и счётчик присоединений.
- «У меня тоже» через сервер; повторное увеличение счётчика клиентом отсутствует. Отдельный список присоединённых проблем.
- Три шага подачи: описание, место, проверка. Категория, описание 10–2000 Unicode code points, подтверждённая точка и отдельное согласие на публикацию обязательны. Поиск адресов через backend, ручной выбор точки на карте.
- Защита от двойной отправки: стабильный client_request_id и Idempotency-Key, объединение одновременных запросов, проверка результата по ID после неопределённого сетевого исхода. До разрешения неопределённого исхода исходные поля блокируются.
- Автосохранение серверного черновика в защищённом хранилище, изоляция по аккаунту и адресу backend, восстановление после перезапуска, очистка после успешной подачи. Сохранение/удаление при выходе; автоматической отправки нет.
- Собственные заявки до модерации читаются через приватные методы. Публичная лента получает только серверные опубликованные проблемы. Демонстрационные записи backend сохраняют метку в заголовке.
- Уточнение своего обращения, отзыв, подписка на проблему, обратная связь по результату и жалоба.
- SMS-вход, ротация refresh-токена, профиль, согласия и юридические документы перед входом, сохранённые места, экспорт, выход и удаление аккаунта. Тестовый экран регистрации push-устройства.
- «Мой дом»: серверный список домов; полноценный кабинет дома ещё не реализован.

## Архитектура

lib/backend.dart — HTTP, локализованные ошибки и защищённая сессия. lib/civic_repository.dart — интерфейс CivicRepository, серверный адаптер, валидация, приватный черновик и идемпотентная отправка. lib/civic_home.dart, civic_form.dart, civic_detail.dart — серверный сценарий. lib/domain.dart — отдельные интерфейсы и локальный DemoRepository; старый демо-сценарий доступен через QOGAM_DEMO. Исходные ТЗ, дизайн и HTML-прототип в docs сохранены.

## Проверки

```powershell
dart format --output=none --set-exit-if-changed lib test
flutter analyze --no-pub
flutter test --no-pub
flutter test --no-pub --dart-define=QOGAM_LIVE_API_TEST=true test/backend_live_test.dart
flutter build apk --debug
```

Обычные тесты используют изолированные фикстуры: валидация, уникальное присоединение, повторная отправка, восстановление и изоляция черновика, сессии, серверная карта/фильтры, три шага и компактный kk-интерфейс при масштабе текста 200%. Live-тест выполняет только чтение справочников, границ города, юридических документов, карты, списка, карточки и истории на ru/kk; по умолчанию отключён. Отправка SMS и изменения настоящих данных этим тестом не выполняются.

## Дальнейшая работа и ограничения

API 0.3.1 содержит 119 операций. Текущий этап подключает основной сценарий жителя; все операции Swagger не считаются реализованными.

Следующие функции: загрузка фото и отслеживание обработки медиа, похожие проблемы, обратное геокодирование и проверка границы города на клиенте, редактирование и отмена присоединения, список подписок, уведомления и автоматический Firebase/APNs-токен. Далее — членство/приглашения дома, новости, приватные заявки дома, объявления и кабинет сотрудников с MFA. Сервер проверяет географические ограничения и права независимо от клиента.

Нужен тестовый аккаунт для проверки реального OTP и защищённых операций на staging. На физическом телефоне текущий сценарий не проверен; телефон не изменялся. Казахские тексты требуют редакторской проверки.

Для production нужны HTTPS и доступный с устройства media origin. Сейчас разрешён HTTP только для конкретных адресов разработки: API 10.8.0.53 и media 10.177.52.82. Подписанные медиа-ссылки сервер выдаёт с ограниченным сроком; они не сохраняются в черновике.

Плитки OSM требуют интернета, атрибуция видна на карте. Провайдер настраивается через MAP_TILE_URL; при смене нужно обновить атрибуцию. Для production следует согласовать провайдера и лимиты нагрузки. GPS пока не подключён.

## Полная интеграция Swagger — 10 октября 2026

Подключены все 119 операций API 0.3.1. Реестр и ограничения: [docs/API_COVERAGE.md](docs/API_COVERAGE.md).
Кнопка уведомлений в верхней панели и «Сервисы» в профиле открывают уведомления, объявления, подписки, дома, приглашения и заявки ОСИ. Карточка дома открывается в «Мой дом» после входа. Кабинеты сотрудников и администратора доступны по роли после MFA; настройка аутентификатора находится в профиле.

Фото выбираются из галереи, загружаются multipart, сохраняются в черновике как media_ids и передаются при подаче. Добавлены обратное геокодирование, похожие проблемы, правка обращения и отмена присоединения. Административные формы поддерживают схемы Swagger, включая варианты действий, nullable и expected_revision. Приватная заявка ОСИ при неопределённом результате восстанавливает прежний payload из защищённого хранилища.

Для обновления клиента после замены схемы: `python3 tool/generate_contract.py`. Проверка полного реестра: `flutter test test/contract_test.dart`. Полные проверки: `flutter analyze`, `flutter test`, `flutter build apk --debug`.

Защищённые операции проверяются на MockClient; для проверки на сервере и устройстве нужны тестовые аккаунты. Автоматическое получение push-токена требует Firebase/APNs-конфигурации; управление токенами через API реализовано.

Проверки этого этапа: 163 автоматических теста прошли, сетевой smoke test ru/kk прошёл отдельно; flutter analyze без замечаний, форматирование и git diff --check чистые. Debug APK собран: `build/app/outputs/flutter-apk/app-debug.apk`. iOS и native photo picker на физическом устройстве не проверены.
