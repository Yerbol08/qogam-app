# Qogam — первый этап

Flutter-приложение Android/iOS: аккаунт, места и справочники подключены к backend; обращения работают с отдельным демонстрационным источником. Исходные ТЗ, PDF-дизайн и HTML-прототип в docs сохранены без изменений. AGENTS.md и отдельные SVG-макеты отсутствовали. SVG встроены в HTML-прототип. Пилот в демо — Астана.

## Запуск

Окружение разработки: Flutter 3.41.8 stable, Dart 3.11.5; Android SDK 36. flutter doctor -v: проблем нет.

```powershell
flutter pub get
flutter devices
flutter run -d <device-id>
```

Для Android подключите телефон с USB debugging либо запустите эмулятор в Android Studio. Сборка и установка:

```powershell
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

APK: `build/app/outputs/flutter-apk/app-debug.apk`. Это debug-сборка, не предназначенная для магазина.
Для iOS нужен Mac с Xcode: `flutter pub get`, `flutter run` на iOS-устройстве/симуляторе. iOS-проект создан; iOS-сборка на Windows не проверена.

## Реализовано

- Светлая тема из ТЗ: primary #087F75, фон #F5F8F7, поверхности, статусы и геометрия компонентов. Общие Panel и StatusBadge.
- Нижние разделы Рядом / Мои заявки / Мой дом / Профиль; карточка, форма и подтверждение через Navigator.
- Полные словари интерфейса ru/kk, платформенная локализация, переключение языка в профиле, верхней панели и форме. Пользовательский текст не переводится.
- Опубликованные демо-проблемы и все шесть категорий; пустое состояние фильтра.
- Карточка, статус, описание, место, история, источник и дата; уникальное локальное присоединение, сохранение между запусками.
- Три шага подачи, проверка категории, длины описания после trim (10–2000 Unicode code points), адреса, координат и подтверждения точки; отдельное согласие выключено по умолчанию.
- Блокировка кнопки во время отправки, сериализация операций, стабильный client_request_id и повторное получение прежнего результата. После подачи обращение только в своих заявках, статус На модерации.
- Автосохранение полей черновика в SharedPreferences при изменении, восстановление при перезапуске, очистка после успеха. Нет автоматической отправки.
- Основные экраны дома и профиля с явными обозначениями будущих функций.

## Архитектура и демо

`lib/domain.dart`: модели Draft/Problem, интерфейсы DraftRepository и ProblemRepository, отдельная реализация DemoRepository. Ключи данных имеют префикс demo. UI сейчас получает демо-реализацию при запуске; перед подключением backend нужно внедрить адаптер и контроллер загрузки/пагинации.
`lib/strings.dart`: одинаковые ключи ru/kk. `lib/main.dart`: запуск и навигация; `lib/ui.dart`: тема и общие компоненты; `lib/pages.dart`: основные разделы и подтверждение; `lib/detail.dart` и `lib/report_form.dart`: карточка и форма.

Точка выбирается вручную на интерактивной карте Астаны; это реальная картографическая подложка, но геокодер и GPS ещё не подключены. Исходные опубликованные примеры не являются реальными происшествиями. Демо-обращения используют локального демо-жителя независимо от реального аккаунта в профиле. Данные обращений хранятся локально; главная карта загружает плитки через интернет. SharedPreferences подходит для демо, но не для production-хранения токенов или приватных данных.

## Следующий этап и ограничения

Возврат после авторизации к подаче реального обращения; выбор города для обращений; карта, поиск адреса, проверка границ города и похожие обращения; до пяти фото и безопасные публичные копии; реальные временные события/организации и комментарии; сетевые состояния и серверная пагинация; редактируемый заголовок; выбор сохранить/удалить черновик при выходе; подписки, push и обратная связь по результату.

Мой дом: подтверждение участия, приглашения, реальные новости и контакты ОСИ, приватные заявки и история. Профиль: настройки уведомлений, полные условия/политика и помощь. Телефонный вход, имя, язык, места, экспорт, выход и удаление аккаунта подключены к текущему API.

Казахские тексты требуют редакторской проверки. Не проверено на физическом Android/iOS. История демо упрощена: события используют демонстрационную дату создания; реальный backend должен передавать дату, роль, организацию и публичный комментарий каждого события.

## Что нужно от backend

Версионированный OpenAPI и staging с префиксом `/api/v1`, тестовыми пользователями, городом и организацией. Раздельные публичные и приватные DTO, серверная проверка прав.

- Справочники городов/категорий с ru/kk и географическими границами.
- Публичная лента проблем: city, bbox, category, status, cursor; карточка с описанием, безопасными media, статусом, revision, числом присоединений и историей событий.
- Уникальное присоединение пользователя к проблеме: атомарный upsert, joined_by_me и актуальный supporters_count; список присоединённых.
- `POST /reports`: client_request_id, city_id, category_id, title, description, location (WGS84), address_text, media_ids, publication_confirmed; Idempotency-Key. Ответ: id, display_number, moderation_state, workflow_state, created_at, revision.
- Поиск своего обращения по client_request_id после тайм-аута; одинаковый ключ возвращает прежний результат, изменённый payload — 409. Список своих, детали и дальнейшая правка. Непроверенные обращения исключены из публичных ответов.
- OTP/verify/refresh/logout, профиль, версии и фиксация согласий; поля ошибок для 422, 401/403, 409, retry_after для 429/503 и trace_id.
- Геокодер и похожие проблемы; upload API, обработка/модерация фото и разделение приватных оригиналов и публичных копий.
- Следующий этап: приватные адреса, дом/членство/ОСИ, уведомления/unread count/push tokens, запрос повторного открытия.

Сервер должен независимо повторять всю валидацию, ограничения города, уникальность присоединений и идемпотентность; UI-проверки не заменяют эти гарантии.

## Обновление интерфейса и карты — 6 октября 2026

Главный экран переработан: выразительная типографика, компактная панель города, поиск по демо-проблемам, переключение Карта/Список, категории с иконками, карточки и закреплённая кнопка подачи. Обновлены общие поля, кнопки, карточки и нижняя навигация.

Главная карта теперь настоящая интерактивная карта Астаны на flutter_map 8.3.2 с OpenStreetMap. Есть перемещение, масштабирование, центр района, маркеры по категориям и переход в карточку. Категория и поиск применяются одновременно к маркерам и списку. На карту попадают только опубликованные проблемы с координатами. Адреса/координаты примеров демонстрационные, не подтверждают реальные происшествия. После аудита дизайна форма подачи использует тот же картографический компонент для выбора точки.

Плитки загружаются только для просмотра; flutter_map использует штатный HTTP-кэш. На карте постоянно видна атрибуция со ссылкой на OpenStreetMap. URL настраивается через `--dart-define=MAP_TILE_URL=...`; при смене провайдера нужно также обновить атрибуцию и условия. Для production требуется выбрать провайдера под ожидаемую нагрузку и его условия. Правила: https://operations.osmfoundation.org/policies/tiles/ . Документация: https://docs.fleaflet.dev/layers/tile-layer . При ошибке загрузки карта предлагает открыть список. GPS/геокодер не подключены; кнопка центра возвращает к району, не определяет местоположение пользователя.

Проверки обновления: 9 тестов успешно, включая общий фильтр карты/списка, переход по маркеру и поиск; kk при 200% тексте; analyze и форматирование без замечаний; debug APK собран. Визуальная проверка Flutter-рендера 390×844 выполнена без сетевых плиток. Android-эмулятор оставался unauthorized в ADB, поэтому реальная загрузка плиток на устройстве ещё не подтверждена. # Контракт backend

Подтверждённый адрес среды разработки: `http://10.8.0.53:8000`.
Проверка Swagger и перечень недостающих API: [docs/BACKEND_CONTRACT.md](docs/BACKEND_CONTRACT.md).
Все 15 операций Swagger подключены через `lib/backend.dart`; экраны — `lib/backend_pages.dart`. Для входа откройте «Профиль» → «Войти по телефону». После входа доступны профиль, места, экспорт, обновление сессии и выход. Удаление аккаунта требует подтверждения. Справочники доступны без входа.

```powershell
flutter run --dart-define=QOGAM_API_URL=http://10.8.0.53:8000
```

Телефону нужен доступ к частной сети/VPN. Для другого HTTP-хоста измените разрешённый адрес в Android network_security_config.xml и iOS Info.plist; для production используйте HTTPS и уберите исключения разработки. Токены сохраняются через защищённое хранилище; Android backup отключён, iOS Keychain entitlement добавлен.

Регистрация push-устройства использует настоящий токен, введённый в тестовом экране; автоматическое получение Firebase/APNs-токена ещё требует настройки провайдера. Для production также нужны полные юридические документы согласий от backend. Серверные методы обращений отсутствуют: «Рядом», «Мои заявки» и «Мой дом» остаются явно демонстрационными и не отправляют обращения на backend.

Проверка доступности API без SMS и изменения данных:

```powershell
flutter test test/backend_live_test.dart --dart-define=QOGAM_LIVE_API_TEST=true
```

Обычный `flutter test` пропускает этот сетевой тест и проверяет все методы на MockClient: точные payload/headers/status, восстановление защищённой сессии, конкурентную ротацию, 401/422/429, таймаут, явные согласия и блокировку повторного входа. Проверена вёрстка новых экранов на 320×640 с казахским языком и текстом 200%. Доступность реального API проверена Flutter-клиентом; реальные OTP и защищённые методы ещё требуют проверки с тестовым номером. iOS на Windows не собирался.
