# Проверка backend — 6 октября 2026

Подтверждённый пользователем Base URL: `http://10.8.0.53:8000`.
Swagger: http://10.8.0.53:8000/docs ; схема: `/openapi.json`.
Проверена версия Qogam API `0.1.0`. Префикс методов — `/v1`.

## Доступно сейчас

Swagger и OpenAPI отвечают HTTP 200. Выполнены только запросы чтения.
`GET /v1/meta` возвращает `environment: local` и `consent_version: 2026-10-01`.
`GET /v1/categories` возвращает 27 категорий, включая подкатегории;
`GET /v1/cities` — город `astana`. Язык задаётся заголовком
`Accept-Language: ru` или `kk`, а не параметром `lang`.

| Функция | Методы в Swagger |
| --- | --- |
| SMS-вход | POST /v1/auth/otp/request, POST /v1/auth/otp/verify |
| Сессия | POST /v1/auth/refresh, POST /v1/auth/logout |
| Профиль | GET/PATCH/DELETE /v1/me, GET /v1/me/export |
| Push-устройство | PUT /v1/me/devices |
| Сохранённые места | GET/POST /v1/me/places, DELETE /v1/me/places/{place_id} |
| Справочники | GET /v1/meta, /v1/categories, /v1/cities |

Защищённые методы используют `Authorization: Bearer <access_token>`.
OTP содержит шесть цифр. При первом входе требуется актуальная версия согласия
из `/v1/meta` и согласие `processing`. Согласия `gov_transfer` и `push`
отдельные; согласие на публичную публикацию обращения в этой схеме отсутствует.
Refresh-токен ротируется; повторное использование отзывает сессии.
Ошибки валидации 422 описаны как `detail[]` с `loc`, `msg`, `type`.
Ответы 401/403/409/429 и формат остальных ошибок в OpenAPI не описаны.

## Чего не хватает для основного сценария

Следующие методы **предлагаются для согласования**, их сейчас нет в Swagger:

| Репозиторий приложения | Необходимый контракт |
| --- | --- |
| published() | Список опубликованных проблем: координаты/bbox или радиус, город, категория, поиск, курсор пагинации |
| Карточка | Проблема по ID: полное описание, статус, координаты, адрес, дата, история с датами, количество присоединений, joined_by_me |
| mine() | Собственные обращения, включая приватные до модерации, с пагинацией |
| joined() | Проблемы, к которым пользователь присоединился |
| join(id) | Идемпотентное присоединение: повтор/конкурентные запросы не увеличивают счётчик; ответ с актуальным счётчиком |
| submit(draft) | Создание обращения с Idempotency-Key, category_code, description, location, address, отдельным publication_consent; ответ с ID, статусом и датой |

Сервер должен проверять описание 10–2000 символов, категорию, допустимые
координаты, подтверждение места и отдельное согласие на публикацию.
До модерации обращение доступно только автору, не в публичной выдаче.
Повторная отправка с тем же ключом возвращает тот же ID; изменённая полезная
нагрузка с этим ключом должна давать явный конфликт.
Нужно согласовать коды статусов и события истории, правила модерации,
формат ошибок и ограничения запросов.

## Изменения клиента при подключении

Текущий `DemoRepository` остаётся самостоятельным демонстрационным источником.
Приложение пока не выполняет запросы к этому backend. Подменять недостающие
серверные методы демонстрационными данными в режиме backend нельзя.

Серверный справочник шире текущего enum Category: `water`, `yards`, `other`
не являются серверными кодами. Нужна модель категории с `code`, `parent_code`,
локализованным названием и иконкой; нельзя молча преобразовывать категории.
Черновики сохраняют исходный код и требуют повторного выбора устаревшего кода.

Внедрение выполняется отдельным сетевым репозиторием через существующие
интерфейсы, с конфигурируемым Base URL, таймаутами и обработкой ошибок.
Нужны экран SMS-входа, явные согласия и защищённое хранилище токенов;
SharedPreferences для токенов не подходит. Повтор создания после сетевого
сбоя использует сохранённый ID черновика как ключ идемпотентности.

Адрес приватный: устройству нужен доступ в эту сеть/VPN. HTTP требует
настройки Android network security и iOS ATS для среды разработки;
для production нужен HTTPS. Доступ с рабочей машины проверен, доступ с
Android/iOS устройства ещё не проверялся. SMS, аккаунты и реальные обращения
во время проверки не создавались.
