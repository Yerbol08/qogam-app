# Текущий контракт — API 0.3.1, 10 октября 2026

Подключены **все 119 операций** актуального Swagger: полный реестр, точки входа в интерфейсе и ограничения — [API_COVERAGE.md](API_COVERAGE.md).
Base URL: `http://10.8.0.53:8000`, Swagger: `/docs`.

Добавлены сервисы уведомлений, объявлений и подписок; членство, приглашения, новости и приватные заявки ОСИ; кабинеты модератора, организации и администратора; MFA; загрузка и проверка фото; обратное геокодирование, похожие проблемы, правка и отмена присоединения.
Формы учитывают DTO, ожидаемую версию, отдельное согласие на публикацию и неизменный payload при неопределённом результате отправки. Фото сохраняются в защищённом черновике как серверные media_ids; исходные изображения не записываются в SharedPreferences.

Все операции проверяются на MockClient; публичное чтение ru/kk также проверено на сервере. Реальные защищённые мутации, MFA и native photo picker требуют проверки на устройстве с тестовым аккаунтом. Автоматическая регистрация Firebase/APNs пока требует конфигурации провайдера.

Чтение действующего API на ru/kk проверено Flutter live-тестом: справочники, граница города, юридические документы, карта, список, карточка и история. Сетевые сбои, повторная отправка, черновик и защищённые операции проверяются изолированными фикстурами. Реальные OTP и операции изменения требуют тестового аккаунта; SMS и записи в staging при проверке не отправлялись.

Остаются загрузка/обработка медиа (в новом обращении media_ids пока пуст), похожие проблемы, обратное геокодирование, правка обращения и отмена присоединения, список подписок, уведомления и автоматическая регистрация Firebase/APNs. Полный дом: членство, приглашения, новости и приватные заявки. Объявления и кабинет сотрудников/MFA также требуют отдельных экранов. Получение существующих фотографий из карточки подключено.

Для backend: предоставить тестовый аккаунт/OTP-механизм и сценарии переходов статусов; обеспечить доступность media origin с телефона, согласовать HTTPS для production. Сейчас API выдаёт подписанные media URL на `http://10.177.52.82:8333`; клиент разрешает этот конкретный HTTP-host для разработки.

Проверки: 31 автоматический тест успешно, 1 live-тест пропускается по умолчанию; отдельный live-прогон успешен. Analyze и форматирование без замечаний; debug APK собран. На физическом телефоне и iOS этот этап пока не проверен.

# Исторический контракт — API 0.2.0, 6 октября 2026

Проверена актуальная схема http://10.8.0.53:8000/openapi.json.
Снимок контракта: [openapi.json](openapi.json). Все 19 операций подключены.

Изменения клиента:
- GET /v1/me/consents и PUT /v1/me/consents/{purpose}: экран согласий, отдельное включение и отзыв добровольных целей, принятие текущей версии обязательного согласия. Отзыв processing выполняется удалением аккаунта в профиле.
- DELETE /v1/me/devices: отключение токена из тестового экрана устройства; токен передаётся в JSON, не в URL. logout поддерживает необязательный push_token.
- PATCH /v1/me/places/{place_id}: редактирование типа, названия, адреса, координат, радиуса и уведомлений. Эти поля доступны также при создании; city_code читается из ответа сервера.
- Профиль: consent_version, изменение city_code, явная очистка имени и города через null.
- RFC 7807: code, request_id, field_errors, retry_after; старый detail[] также поддерживается.

Автоматическое получение Firebase/APNs-токенов требует настройки провайдера и пока отсутствует. Полные юридические документы в схеме не опубликованы. API обращений, присоединений, модерации и дома отсутствуют в версии 0.2.0; соответствующие разделы продолжают использовать демо.

# Проверка backend — 6 октября 2026

Полный запрос backend-разработчику для отправки: [BACKEND_REQUEST.md](BACKEND_REQUEST.md).

Подтверждённый пользователем Base URL: `http://10.8.0.53:8000`.
Swagger: http://10.8.0.53:8000/docs ; схема: `/openapi.json`.
Проверена версия Qogam API `0.1.0`. Префикс методов — `/v1`.

## Доступно сейчас

Swagger и OpenAPI отвечают HTTP 200. Выполнены только запросы чтения.
`GET /v1/meta` возвращает `environment: local` и `consent_version: 2026-10-01`.
`GET /v1/categories` возвращает 27 категорий, включая подкатегории;
`GET /v1/cities` — город `astana`. Язык задаётся заголовком
`Accept-Language: ru` или `kk`, а не параметром `lang`.

| Функция | Методы в Swagger |
| --- | --- |
| SMS-вход | POST /v1/auth/otp/request, POST /v1/auth/otp/verify |
| Сессия | POST /v1/auth/refresh, POST /v1/auth/logout |
| Профиль | GET/PATCH/DELETE /v1/me, GET /v1/me/export |
| Push-устройство | PUT /v1/me/devices |
| Сохранённые места | GET/POST /v1/me/places, DELETE /v1/me/places/{place_id} |
| Справочники | GET /v1/meta, /v1/categories, /v1/cities |

Защищённые методы используют `Authorization: Bearer <access_token>`.
OTP содержит шесть цифр. При первом входе требуется актуальная версия согласия
из `/v1/meta` и согласие `processing`. Согласия `gov_transfer` и `push`
отдельные; согласие на публичную публикацию обращения в этой схеме отсутствует.
Refresh-токен ротируется; повторное использование отзывает сессии.
Ошибки валидации 422 описаны как `detail[]` с `loc`, `msg`, `type`.
Ответы 401/403/409/429 и формат остальных ошибок в OpenAPI не описаны.

## Чего не хватает для основного сценария

Следующие методы **предлагаются для согласования**, их сейчас нет в Swagger:

| Репозиторий приложения | Необходимый контракт |
| --- | --- |
| published() | Список опубликованных проблем: координаты/bbox или радиус, город, категория, поиск, курсор пагинации |
| Карточка | Проблема по ID: полное описание, статус, координаты, адрес, дата, история с датами, количество присоединений, joined_by_me |
| mine() | Собственные обращения, включая приватные до модерации, с пагинацией |
| joined() | Проблемы, к которым пользователь присоединился |
| join(id) | Идемпотентное присоединение: повтор/конкурентные запросы не увеличивают счётчик; ответ с актуальным счётчиком |
| submit(draft) | Создание обращения с Idempotency-Key, category_code, description, location, address, отдельным publication_consent; ответ с ID, статусом и датой |

Сервер должен проверять описание 10–2000 символов, категорию, допустимые
координаты, подтверждение места и отдельное согласие на публикацию.
До модерации обращение доступно только автору, не в публичной выдаче.
Повторная отправка с тем же ключом возвращает тот же ID; изменённая полезная
нагрузка с этим ключом должна давать явный конфликт.
Нужно согласовать коды статусов и события истории, правила модерации,
формат ошибок и ограничения запросов.

## Изменения клиента при подключении

Все 15 операций текущего Swagger интегрированы в `lib/backend.dart`.
Раздел «Профиль» использует реальный аккаунт и помечен «Сервер»;
в нём доступны SMS-вход, редактирование/удаление аккаунта, экспорт JSON,
обновление сессии, выход, сохранённые места и серверные справочники.
`DemoRepository` остаётся самостоятельным источником обращений и не
связан с серверным аккаунтом. Обращения и «Мой дом» помечены «Демо».

Серверный справочник шире текущего enum Category: `water`, `yards`, `other`
не являются серверными кодами. Нужна модель категории с `code`, `parent_code`,
локализованным названием и иконкой; нельзя молча преобразовывать категории.
Черновики сохраняют исходный код и требуют повторного выбора устаревшего кода.

Сетевой клиент принимает Base URL через `--dart-define=QOGAM_API_URL=...`,
добавляет Accept-Language и Bearer, ограничивает запросы 15 секундами,
обрабатывает 204, 401, 403, 404, 409, 422, 429 и сетевые ошибки.
Перенаправления отключены, чтобы не отправлять токены на другой адрес.
Токены хранятся через flutter_secure_storage отдельно для каждого Base URL.
Защищённые запросы и изменения сессии идут последовательно; при истечении
access-токена или 401 выполняется одна ротация и один повтор.
При неясном результате ротации (например, таймаут) сессия удаляется,
чтобы не использовать уже потреблённый refresh-токен повторно.
После успешного выхода/удаления аккаунта токены удаляются; при сетевой
ошибке выхода можно повторить действие, сессия не скрывается локально.

Вход запрашивает версию согласий у сервера, обязательное processing
и отдельные добровольные gov_transfer/push не отмечены заранее.
Тексты полных юридических документов в API отсутствуют: перед production
нужны ссылки/тексты документов по версии и локали, просмотр до согласия.

PUT /v1/me/devices подключён через экран регистрации настоящего токена
для тестирования. Firebase/APNs credentials не предоставлены: автоматическое
получение токена, его обновление и доставка push пока не реализованы.
Серверный справочник отображается отдельно от категорий демо-обращений.
Подключение самих обращений ждёт API из таблицы выше.

Адрес приватный: устройству нужен доступ в эту сеть/VPN. HTTP требует
настройки Android network security и iOS ATS для среды разработки —
исключения для `10.8.0.53` добавлены;
для production нужен HTTPS. Доступ с рабочей машины проверен, доступ с
Android/iOS устройства ещё не проверялся. SMS, аккаунты и реальные обращения
во время проверки не создавались.
